## 1. Tēmas nosaukums

**Banku noguldījumu un krājkontu procentu likmju automatizēta skrāpēšana un analīze ar MI atbalstītu skriptu uzturēšanu**

## 2. Problēmas apraksts un aktualitāte

Banku noguldījumu un krājkontu likmes regulāri jāapkopo un jāsalīdzina (piemēram, tirgus pārskatiem). Šobrīd tas prasa daudz roku darba: jāatver katras bankas mājaslapa, jāatrod pareizais produkts un segments, jāpārraksta likmes un jāsakārto tabulā.

Darbu daļēji var automatizēt ar skrāpēšanas skriptiem, taču bankas bieži maina lapu struktūru, un tad skripti pārstāj darboties. Lai skriptu salabotu, vajadzīgas programmēšanas zināšanas un laiks. Problēmas būtība tāpēc ir ne tikai pati datu iegūšana, bet arī tas, ka skriptus ir grūti uzturēt ilgtermiņā.

## 3. Darba mērķis

Izveidot sistēmu, kas:
- reizi nedēļā automātiski iegūst termiņnoguldījumu un krājkontu EUR likmes no lietotāja norādītām Latvijas un Baltijas banku mājaslapām;
- saglabā likmju vēsturi un izveido standartizētu Excel pārskatu;
- ļauj lietotājam tīmekļa saskarnē analizēt rezultātus un ar MI asistenta palīdzību ātri un droši salabot skriptus, kas vairs nedarbojas.

## 4. Uzdevumi

1. Izstrādāt skrāpēšanas skriptus (katrai bankai un produktam savu) ar kopīgu bāzes moduli un vienotu datu formātu.
2. Iegūt Latvijas banku juridiskos nosaukumus no Uzņēmumu reģistra atvērtajiem datiem (data.gov.lv).
3. Saglabāt katra palaidiena likmes un statusu vēsturē (CSV) un izveidot Excel failu ar 8 lapām pēc lietotāja noteikta formāta.
4. Uzstādīt Linux virtuālo mašīnu (izstrādē Google Cloud, vēlāk Azure), kas skrāpē pēc grafika (cron), sūta e-pasta kopsavilkumu un glabā skriptu izmaiņu vēsturi vietējā Git repozitorijā ar rezerves kopiju.
5. Izveidot Shiny for Python lietotni Posit Connect vidē: rezultātu analītika (likmju izmaiņas, grafiki), failu lejupielāde, banku saraksta un Excel termiņu pārvaldība, skriptu apskate, vēsture un salīdzinājums.
6. Ieviest skriptu testēšanu Posit vidē atsevišķā procesā (ar laika limitu un bez piekļuves slepenajiem datiem).
7. Integrēt MI čatu (`chatlas`, rīku izsaukšana), kas palīdz labot nestrādājošus skriptus; labojums uz VM nonāk tikai pēc veiksmīga testa un lietotāja apstiprinājuma.
8. Nodrošināt divu lietotāju darbu bez konfliktiem (bloķēšanas atzīmes, kontrolsummu pārbaude).
9. Pārcelt sistēmu uz ieviešanas vidi (Azure VM, organizācijas Posit Connect, Open WebUI, GitLab), mainot tikai iestatījumus, nevis kodu.

## 5. Mērķauditorija

Analītiķi vai darbinieki (divi lietotāji), kuriem regulāri jāapkopo banku likmes. Lietotājiem nav nepieciešamas padziļinātas programmēšanas zināšanas — skriptu labošanā palīdz MI asistents.

## 6. Risinājuma apraksts

Sistēmai ir divas galvenās daļas:

- **Linux VM** — glabā galveno banku skriptu, banku saraksta un vēstures kopiju, reizi nedēļā palaiž skrāpēšanu, izveido Excel failu (tikai tad, ja izdevies visām bankām) un nosūta e-pastu par rezultātu. VM nav MI, un tā neiegūst kodu no Git.
- **Shiny lietotne Posit Connect vidē** — sazinās ar VM caur SSH/SFTP: nolasa rezultātus un skriptus, ļauj tos labot (ar roku vai ar MI), testē un pēc apstiprinājuma nosūta atpakaļ uz VM kā Git commit.

Svarīgākie principi:
- **drošība** — atslēgas un paroles tikai vides mainīgajos; uz VM nonāk tikai notestēts un apstiprināts kods;
- **pārnesamība** — viens un tas pats kods izstrādes un ieviešanas vidē, atšķiras tikai `.env` iestatījumi;
- **neatkarība no konkrēta MI pakalpojuma** — izstrādē Claude (Anthropic API), ieviešanā Open WebUI ar OpenAI saderīgu API; MI rīki ir vienkārši, lai ar tiem tiktu galā arī mazāki modeļi.

## 7. Izmantojamās tehnoloģijas

| Joma | Tehnoloģija |
|---|---|
| Valoda | Python 3.11+ |

| Saskarne | Shiny for Python, Plotly, CodeMirror |
| MI | chatlas; Claude (izstrādē), Open WebUI (ieviešanā) |
| Serveris | Ubuntu 24.04 LTS VM (Google Cloud → Azure), cron, Git |
| Saziņa | SSH/SFTP (paramiko) |
| Izvietošana | Posit Connect Cloud → Posit Connect, rsconnect |
| Koda glabāšana | GitHub → GitLab |
| Testi | pytest ar saglabātiem HTML paraugiem |

## 8. Plānotie rezultāti

- Strādājoša sistēma, kas reizi nedēļā automātiski iegūst likmes no visām `banks.csv` norādītajām bankām.
- Likmju vēsture un Excel pārskats `likmes_GGGG-MM-DD.xlsx` lietotāja noteiktajā formātā.
- Tīmekļa lietotne rezultātu analīzei un skriptu pārvaldībai ar MI asistentu.
- Dokumentācija: uzstādīšana (`vm/setup.sh`), izvietošana, vides mainīgie un VM pārcelšanas instrukcija.

## 10. Riski un to mazināšana

| Risks | Mazināšana |
|---|---|
| Bankas maina lapu struktūru | statusa uzraudzība, e-pasts par kļūdu, ātra labošana ar MI |
| MI sagatavo kļūdainu skriptu | obligāts tests atsevišķā procesā un lietotāja apstiprinājums |
| Mazāks MI modelis ieviešanas vidē slikti izmanto rīkus | vienkārši rīki, agrīna pārbaude ar mazāku modeli |
| Bankas lapa ielādē likmes ar JavaScript | Playwright (Chromium) |
| Divi lietotāji vienlaikus labo vienu skriptu | bloķēšanas atzīmes un kontrolsummu pārbaude |
| Datu zudums Posit pagaidu failu sistēmā | pastāvīgā kopija tikai VM, Git rezerves repozitorijs |

## 11. Ierobežojumi

- Tiek skrāpētas tikai EUR likmes un tikai viens paveids katram produktam.
- Netiek apieta pieteikšanās vai aizsardzības mehānismi; skrāpēšana ir pieklājīga (saprātīgi intervāli, korekts User-Agent).
- Saskarne un e-pasti latviešu valodā.

## 12. Novērtēšanas kritēriji

Darbu var uzskatīt par izdevušos, ja:
- visas `banks.csv` bankas tiek noskrāpētas pēc grafika un rezultāti atbilst noteiktajam datu formātam;
- nestrādājošu skriptu var salabot no saskarnes (ar MI vai ar roku) bez tiešas piekļuves serverim;
- sistēmu var pārcelt uz ieviešanas vidi, mainot tikai iestatījumus.
